# コンポーネントプレビューのUIルール

Storybookは実コンポーネントの表示と設定変更、利用ルールの参照に使います。TIcon・TBrand・TLogoのDefaultストーリーは「コンポーネント」直下に維持し、利用ルールを「コンポーネント/個別ルール」に分けて置きます。Astro側への説明ページ移設は別作業です。

## CanvasとControls

- 「アイコン/使用例/基本アイコン/bell-off」と同じCSF形式とし、`layout: centered`で公開入口の実コンポーネントを1つ中央に表示します。`!autodocs`を指定します。
- Canvasに見出し、説明、独自の設定欄や枠、Props表、使用コード・コピー、比較表示、折りたたみ、関連資料一覧を置きません。
- 設定はStorybook標準のControlsとargsで管理します。変更は見本に反映され、URLから復元できます。UIからのストーリー保存は無効にします。
- Controlsと標準パネルの設定はbell-offと揃えます。表示目的のイベントやplay関数は追加しません。

| コンポーネント | Controls | 初期値 |
| --- | --- | --- |
| TIcon | framework・name・size・color | React・bell・24px・currentColor |
| TBrand | framework・text・size | React・Tokiwagi UI・32px |
| TLogo | framework・size・decorative | React・32px・false |
| THeader | framework・tone・disabled・view | React・neutral・false・month（合成例） |
| THeaderSection | framework・position | React・left（親THeader内の見本） |
| THeaderButton | framework・tone・content・text・icon・selected・disabled | React・neutral・文字＋アイコン・操作・share・unset・false |
| THeaderButtonGroup | framework・tone・disabled・view | React・neutral・false・month（合成例） |

ヘッダー4部品も同じ共通描画と標準Controlsを使います。THeaderは幅1440pxを上限にビューポートへ収まる合成例を1つ表示し、狭い画面では部品内部を横スクロールします。selectedのunsetは未指定、offはfalse、onはtrueとして渡します。Astroは公開部品の状態別テンプレートを実描画して収録します。THeaderButtonの文字のみ／アイコンのみ／文字＋アイコンはcontentで切り替え、textと全329種のiconを変更できます。アイコンのみではtextを読み上げ名に使い、空白だけの文言は「操作」に置き換えます。日本語・記号・空文字の入力も文字コードをURLに保持して復元します。Astroは実ボタンのテンプレートと実TIconの生成済みHTMLを組み合わせ、入力テキストをHTMLとして解釈しません。THeaderは子のTHeaderSectionでleft・center・rightを指定する構成です。THeaderSectionの見本は親THeaderの中に1つ表示し、positionで左右・中央の配置を変更します。見本にアプリ固有のメニューや日付移動処理は追加しません。

方式はReact・Vue・Astroの順とし、切り替えても他の設定を保持します。TIconの公開名は329種、サイズは16・20・24・32px、色は継承・ニュートラル・7色のプライマリーから選びます。色はbell-offと同じ既存トークンへのmappingで指定し、URLには選択肢のキーを保持します。TLogo・TBrandは32・64・128pxで、原本の固定配色と余白を維持します。

## 個別ルール

- 本文の管理元は`components/<コンポーネント名>/README.md`です。`src/stories/component-rules/<コンポーネント名>.mdx`は対応する原本を`?raw`で読み込み、Markdownで表示する薄いページとします。本文を複製しません。
- 分類は「コンポーネント/個別ルール/TBrand・TIcon・TLogo」、Docs IDは`components-tbrand-rules`・`components-ticon-rules`・`components-tlogo-rules`です。既存DefaultストーリーのIDとURLは維持します。
- 本文は「概要」「使用場面」「状態の表し方」「使用しない場面」「表示とアクセシビリティ」「関連コンポーネントと使い分け」の6セクションに揃えます。公開API・Props表・利用コード・SSR・CSPなどの導入説明はリポジトリのREADMEに保持します。
- 個別READMEに「使用例を見る」と関連資料へのリンクを置きます。原本ではリポジトリ内の相対パスを使い、`component-readme.ts`でStorybookの閲覧先へ変換します。Canvasにはリンクや説明を追加しません。
- 既存アイコンの個別ルールとロゴ原本の使用ルールは、それぞれの管理元を維持します。

## 共通の描画処理

`components/component-story.ts`のrenderComponentStory・componentStoryParameters・frameworkControlを再利用します。`components/ComponentPreview.tsx`がReact・Vue・Astroの実コンポーネントを描画します。Storybook専用コードはアプリ向け公開入口からexportしません。

- args更新には同じReactのrootとVueアプリを使います。方式切り替え時は旧方式の表示を解放し、離脱時にReactのrootと内部Vueアプリを解放します。
- Astroは既存の生成済みHTMLとcreateAstroPreviewLoaderを利用します。SVGのID分離と親からの色継承を維持します。
- 読み込み中はrole=status、失敗時はrole=alertと「再試行」を表示します。正常時は見本だけに戻します。離脱後の古い応答は画面へ反映しません。
- 小さい画面でも実コンポーネントを縮小しません。既存トークンと公開APIに従います。

## 検証

390px・1440pxで中央の見本、Controlsの操作とキーボードフォーカス、方式切り替え時の設定保持、URL再読み込みを確認します。Astroの読み込み・失敗・再試行、Vueのアンマウント、moon/toolのクリッピング、静的Storybookでの3方式の表示も検証します。個別ルールはREADMEとMDXの一対一の対応、6セクション、本文・表・リンクの表示と横はみ出し、キーボード操作、原本とStorybook双方でのリンク解決を確認します。テスト・型検査・両ビルドはAGENTS.mdに従います。
