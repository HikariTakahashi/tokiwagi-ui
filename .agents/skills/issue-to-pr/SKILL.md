# Issue から PR まで

対象は `HikariTakahashi/tokiwagi-ui`。`AGENTS.md` と関連するリポジトリの指示を確認し、次の順に進める。既存の作業ツリーの変更は保持する。

1. **Issue を特定する。** 既存 Issue を検索し、候補のタイトル、番号、要点を比較する。ユーザーの依頼と一致する Issue が一つなら採用し、複数あって判断できなければ候補を示して選択を求める。該当する Issue がなければ新規 Issue と判断する。
2. **必要なら Issue を作成する。** 新規 Issue の作成には [github-issue](../github-issue/SKILL.md) skill を使用し、作成した番号と URL を記録する。重複する Issue を作らない。
3. **ブランチを作成する。** 対象 Issue、既存の変更、現在のブランチ、基点を確認してから作業ブランチを作る。Issue 番号を名前に含め、既存ブランチと衝突しない名前を選ぶ。
4. **実装する。** Issue の受け入れ条件に沿って変更し、関連する検証を実施する。変更内容と検証結果をまとめる。
5. **コミットする。** [conventional-commit](../conventional-commit/SKILL.md) skill を読み、対象ファイルと具体的なコミット名を提示してユーザーの明示的な許可を得る。許可後に対象ファイルをステージし、提示した名前でコミットする。許可がない間はコミットしない。
6. **PR は指示された場合のみ作成する。** ユーザーから PR 作成を命じられたら [github-pr](../github-pr/SKILL.md) skill を使用する。PR に Issue との関連、変更概要、検証結果を含める。同 skill にコミット手順があっても、コミット済みの変更を再度コミットする必要はない。追加コミットが必要なら、手順5の許可を改めて得る。PR 作成の指示がなければ、コミット後に結果を報告して待つ。

各 skill を利用できない場合、その skill が必要な操作を止めて不足をユーザーに伝える。
