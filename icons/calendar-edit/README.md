# calendar-edit

ファイル：`calendar-edit.svg` · 状態：詳細ルール案（SVG収録済み・既存画面への適用前）

## 概要

別名：`date`、`schedule`、`event`、`カレンダー`、`日付`、`予定`、`pencil`、`pen`、`modify`、`編集`、`鉛筆`、`ペン`

予定を対象とする図柄。既存の内容を変更するための編集操作を表す。

## 使用場面

- 「予定：編集する」：対象の既存内容を変更する。編集開始だけでは変更を保存しない。
- 予定とほかの対象が混在し、対象を図柄でも区別したい場所で使用する。予定詳細の中など対象が明確な場所では、基本形の [`edit`](?path=/docs/icons-edit--docs) を優先する。
- 既存フロントエンドの予定入力・編集案内の候補。新規作成と既存予定の編集はラベルで区別する。

## 状態の表し方

- 操作・状態の適用範囲を示す。1件の予定なのか、選択した複数件・一覧全体なのかをラベルや周辺文言で明示する。
- 閲覧中・編集中・未保存を文言やフォームの状態で示す。編集アイコンだけで保存完了を伝えない。
- アイコンの表示と実際の状態を一致させる。操作不可の場合は操作部品側で無効状態と必要な理由を示す。

## 使用しない場面

- 新規作成、保存、削除、コード実行。
- 操作できない状態表示を、押せるボタンのように見せること。
- 予定に限定されないアプリ全体の操作や、別の種類の対象への操作。

## 表示とアクセシビリティ

- 「予定：編集する」など対象と操作を伝える。行内に同じボタンが並ぶ場合は、対象の名称も読み上げ名に含める。
- どの項目を編集するかを名前に含め、編集開始後の入力位置を分かりやすくする。
- 初めて使う場所や意味が曖昧な場所ではテキストラベルを併記する。隣接テキストと同じ意味のアイコンは装飾として扱い、二重に読み上げさせない。
- 状態は色だけで区別せず、文言・図柄・操作部品の状態でも伝える。ツールチップだけに意味を依存させない。
- サイズ・色・余白・操作領域・フォーカス表示は共通のアイコン／ボタン規則に従う。線幅や縦横比を個別に変更せず、キーボードでも操作とフォーカス位置を確認できるようにする。

## 関連アイコンと使い分け

- [`edit`](?path=/docs/icons-edit--docs)：対象や枠のない基本形。周辺の文脈で対象が明確な場合はこちらを基本とする。
- [`task-edit`](?path=/docs/icons-task-edit--docs)：タスクを対象にする場合。
- [`plus`](?path=/docs/icons-plus--docs)：新規項目の追加・数量の増加。
- [`save`](?path=/docs/icons-save--docs)：アプリ内の変更を保存する。
- [`code`](?path=/docs/icons-code--docs)：コードの閲覧・編集。
