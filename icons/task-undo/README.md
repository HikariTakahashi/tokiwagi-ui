# task-undo

ファイル：`task-undo.svg` · 状態：詳細ルール案（SVG収録済み・既存画面への適用前）

## 概要

別名：`todo`、`checklist`、`タスク`、`作業`、`やること`、`revert`、`取り消し`、`元に戻す`

タスクを対象とする図柄。直前の操作を取り消し、適用前の状態に戻すことを表す。

## 使用場面

- 「タスク：変更を取り消す」：対象への直前の操作を戻す。戻せる範囲と操作名を示す。
- タスクとほかの対象が混在し、対象を図柄でも区別したい場所で使用する。タスク詳細の中など対象が明確な場所では、基本形の [`undo`](?path=/docs/icons-undo--docs) を優先する。

## 状態の表し方

- 操作・状態の適用範囲を示す。1件のタスクなのか、選択した複数件・一覧全体なのかをラベルや周辺文言で明示する。
- 取り消せる対象と範囲を示す。画面を閉じるキャンセルと区別する。
- アイコンの表示と実際の状態を一致させる。操作不可の場合は操作部品側で無効状態と必要な理由を示す。

## 使用しない場面

- 過去の全履歴の消去、通信再試行、現在の画面を閉じる。
- 操作できない状態表示を、押せるボタンのように見せること。
- タスクに限定されないアプリ全体の操作や、別の種類の対象への操作。

## 表示とアクセシビリティ

- 「タスク：変更を取り消す」など対象と操作を伝える。行内に同じボタンが並ぶ場合は、対象の名称も読み上げ名に含める。
- 「タスクの削除を取り消す」など戻す操作を可能な範囲で示す。
- 初めて使う場所や意味が曖昧な場所ではテキストラベルを併記する。隣接テキストと同じ意味のアイコンは装飾として扱い、二重に読み上げさせない。
- 状態は色だけで区別せず、文言・図柄・操作部品の状態でも伝える。ツールチップだけに意味を依存させない。
- サイズ・色・余白・操作領域・フォーカス表示は共通のアイコン／ボタン規則に従う。線幅や縦横比を個別に変更せず、キーボードでも操作とフォーカス位置を確認できるようにする。

## 関連アイコンと使い分け

- [`undo`](?path=/docs/icons-undo--docs)：対象や枠のない基本形。周辺の文脈で対象が明確な場合はこちらを基本とする。
- [`calendar-undo`](?path=/docs/icons-calendar-undo--docs)：予定を対象にする場合。
- [`redo`](?path=/docs/icons-redo--docs)：取り消した操作の再適用。
- [`history`](?path=/docs/icons-history--docs)：過去の変更の閲覧。復元操作そのものとは区別する。
- [`close`](?path=/docs/icons-close--docs)：表示を閉じる・操作をキャンセルする。
