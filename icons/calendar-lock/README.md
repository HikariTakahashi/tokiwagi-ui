# calendar-lock

ファイル：`calendar-lock.svg` · 状態：詳細ルール案（SVG収録済み・既存画面への適用前）

## 概要

別名：`date`、`schedule`、`event`、`カレンダー`、`日付`、`予定`、`padlock`、`protect`、`ロック`、`南京錠`、`鍵`、`保護`

予定を対象とする図柄。ロック・アクセス制限・保護された状態を表す。

## 使用場面

- 「予定：編集をロック」：対象の編集やアクセスを制限する。どの操作が保護されるかを示す。
- 予定とほかの対象が混在し、対象を図柄でも区別したい場所で使用する。予定詳細の中など対象が明確な場所では、基本形の [`lock`](?path=/docs/icons-lock--docs) を優先する。

## 状態の表し方

- 操作・状態の適用範囲を示す。1件の予定なのか、選択した複数件・一覧全体なのかをラベルや周辺文言で明示する。
- 何が保護されるかと解除条件を示す。鍵の図柄だけで暗号化や安全性を保証しない。
- アイコンの表示と実際の状態を一致させる。操作不可の場合は操作部品側で無効状態と必要な理由を示す。

## 使用しない場面

- ログイン状態の単純な表示、通信障害、非表示設定。
- 操作できない状態表示を、押せるボタンのように見せること。
- 予定に限定されないアプリ全体の操作や、別の種類の対象への操作。

## 表示とアクセシビリティ

- 「予定：編集をロック」など対象と操作を伝える。行内に同じボタンが並ぶ場合は、対象の名称も読み上げ名に含める。
- 操作可能なロックと状態表示を区別し、制限理由を読み上げでも確認できるようにする。
- 初めて使う場所や意味が曖昧な場所ではテキストラベルを併記する。隣接テキストと同じ意味のアイコンは装飾として扱い、二重に読み上げさせない。
- 状態は色だけで区別せず、文言・図柄・操作部品の状態でも伝える。ツールチップだけに意味を依存させない。
- サイズ・色・余白・操作領域・フォーカス表示は共通のアイコン／ボタン規則に従う。線幅や縦横比を個別に変更せず、キーボードでも操作とフォーカス位置を確認できるようにする。

## 関連アイコンと使い分け

- [`lock`](?path=/docs/icons-lock--docs)：対象や枠のない基本形。周辺の文脈で対象が明確な場合はこちらを基本とする。
- [`task-lock`](?path=/docs/icons-task-lock--docs)：タスクを対象にする場合。
- [`login`](?path=/docs/icons-login--docs)：アカウントでサービスへログインする操作を表す。
- [`visibility-off`](?path=/docs/icons-visibility-off--docs)：内容を隠す操作・非表示の状態。
- [`edit`](?path=/docs/icons-edit--docs)：既存の内容を変更する。
