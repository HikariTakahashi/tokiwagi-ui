# task-image

ファイル：`task-image.svg` · 状態：詳細ルール案（SVG収録済み・既存画面への適用前）

## 概要

別名：`todo`、`checklist`、`タスク`、`作業`、`やること`、`picture`、`photo`、`画像`、`写真`

タスクを対象とする図柄。画像データ、画像表示、画像の挿入を表す。

## 使用場面

- 「タスク：画像を追加」：対象に関連する画像を追加・表示する。一般ファイルの添付とは区別する。
- タスクとほかの対象が混在し、対象を図柄でも区別したい場所で使用する。タスク詳細の中など対象が明確な場所では、基本形の [`image`](?path=/docs/icons-image--docs) を優先する。

## 状態の表し方

- 操作・状態の適用範囲を示す。1件のタスクなのか、選択した複数件・一覧全体なのかをラベルや周辺文言で明示する。
- 未選択・選択済み・読み込み失敗を区別する。画像アイコンを実画像の内容説明の代用にしない。
- アイコンの表示と実際の状態を一致させる。操作不可の場合は操作部品側で無効状態と必要な理由を示す。

## 使用しない場面

- すべてのファイル形式、撮影機能がない場所での撮影操作。
- 操作できない状態表示を、押せるボタンのように見せること。
- タスクに限定されないアプリ全体の操作や、別の種類の対象への操作。

## 表示とアクセシビリティ

- 「タスク：画像を追加」など対象と操作を伝える。行内に同じボタンが並ぶ場合は、対象の名称も読み上げ名に含める。
- 意味のある実画像には内容の代替テキストを付け、追加ボタンには操作名を付ける。
- 初めて使う場所や意味が曖昧な場所ではテキストラベルを併記する。隣接テキストと同じ意味のアイコンは装飾として扱い、二重に読み上げさせない。
- 状態は色だけで区別せず、文言・図柄・操作部品の状態でも伝える。ツールチップだけに意味を依存させない。
- サイズ・色・余白・操作領域・フォーカス表示は共通のアイコン／ボタン規則に従う。線幅や縦横比を個別に変更せず、キーボードでも操作とフォーカス位置を確認できるようにする。

## 関連アイコンと使い分け

- [`image`](?path=/docs/icons-image--docs)：対象や枠のない基本形。周辺の文脈で対象が明確な場合はこちらを基本とする。
- [`calendar-image`](?path=/docs/icons-calendar-image--docs)：予定を対象にする場合。
- [`paperclip`](?path=/docs/icons-paperclip--docs)：対象への添付。クリップボードへのコピーには使わない。
- [`upload`](?path=/docs/icons-upload--docs)：外部からファイル・データを読み込む。
- [`visibility-off`](?path=/docs/icons-visibility-off--docs)：内容を隠す操作・非表示の状態。
